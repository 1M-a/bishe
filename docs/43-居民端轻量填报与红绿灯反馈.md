# 居民端轻量填报与红绿灯反馈

## 居民操作

居民打开 `/portal` 后用大白话描述事情，可使用手机键盘的语音转文字，也可选择聊天截图/现场照片作为补充。手机号是查询进度所需的唯一必填身份字段；姓名和位置选填。表单使用浏览器/手机系统自动填充，不读取设备通讯录、定位、短信或聊天记录，不采集身份证号。

浏览器提供本地 `TextDetector` 时，截图识别在当前设备执行，识别结果先回填到文本框供居民检查；不支持时仍可上传截图，或粘贴手机系统识别出的文字。上传图像沿用服务端格式、大小、数量校验，以随机文件名保存，SHA-256 写入证据链。相同诉求复用原查询码，附带截图追加到原单；附件失败时明确告知，文字诉求仍保留。

## 状态灯

| 灯色 | 规则 | 居民看到 |
|---|---|---|
| 绿 | 所有事项已办结 | 已办结 |
| 黄 | 已受理或办理中，未超 SLA | 处理中 |
| 红 | 任一未办结工单超过其 SLA，或居民已有未解决异议 | 需关注 |

居民提交或成功查询后，系统把最近记录保存在当前浏览器的签名会话中；首页和查询页提供免输码的最近进度入口。未建立会话的设备仍须手机号加查询码验证，不能只凭手机号检索，避免泄露居民事项。浏览器会话丢失或更换设备时，可用查询码找回。进度页只展示状态灯、查询码和提交时间，不展示内部拆解项、承办流转细节或敏感字段。状态仅由服务端业务状态计算，不接受前端传入的颜色。

## 边界

自动填充依赖居民设备/浏览器已保存信息，不等同于实名核验。截图识别能力取决于浏览器实现；当前 ECS 是 HTTP 地址，部分浏览器会禁用本地识别能力，居民仍可上传图片并通过手机自带识别粘贴文字。要在各类手机上稳定提供 OCR，应先为站点配置 HTTPS，再评估并部署受控的本地 OCR 引擎；居民截图不发送到第三方 OCR 服务。
