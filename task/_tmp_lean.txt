二、P0 组合反馈（核心需求，先做）
2.1 目标
文字、拍照、语音三种反馈平级可选、任意组合：可只用一种、任意两种、或三种一起。三通道全空才拒绝提交。
2.2 前端改造 app/templates/portal/report.html
现有文字 textarea（2000 字）和照片 input（5 张）保留，把"手机键盘语音输入"的提示换成真正的录音通道。
2.3 语音通道四状态（只管语音，不管其他）
2.4 后端改造 app/api/portal.py
2.5 验收
只发文字 / 只发照片 / 只发语音 → 三种单独都能提交成功；
文字+照片 / 文字+语音 / 照片+语音 / 三者一起 → 四种组合都能提交成功；
三通道全空 → 提示"至少选一种反馈方式"，不入库；
拒绝麦克风权限 → 语音置灰但文字/照片仍可提交；
进度页能看到该诉求用了哪几种通道（见第四节标签）。
三、P0 关怀模式
3.1 前端 portal/base.html + portal.css
在页头 p-head-row 里、工作人员入口旁加一个"关怀模式"开关按钮（不用恢复已下线的"我的"页，a.txt 判断正确）。
开关读/写 localStorage.getItem/setItem('xf_care', '1'/'0')；
开启给 body 加 care 类，portal.css 里 body.care 放大字号变量（--font 系列）；
关闭移除 care 类并停止朗读。
3.2 朗读 portal/notice_doc.html
进入公告详情时按 care 状态决定是否用 speechSynthesis 朗读全文；开启关怀模式时从首页进入也自动朗读。浏览器不支持则静默跳过（if (!window.speechSynthesis) return;），不报错。
四、P1 进度标签 + 催办 + 投诉 + 满意度
4.1 进度页加"反馈形式标签"
位置：portal/ticket.html 的进度卡下方。做法：后端 _payload() 返回 channels: ["文字","照片","语音"]（从附件 type 推导），前端渲染成小标签。效果：居民看到系统确实收到了他的语音/照片，直接呼应组合反馈。
4.2 催办（portal.py + ticket.html）
4.3 投诉（新增独立入口）
位置：base.html 底部导航或首页加"投诉"入口，指向新的 /portal/complaint，复用 report.html 的三通道输入组件。后端新建轻量表 Complaint（phone、content、photos、audio、status、created_at），进入人工处理队列。
4.4 满意度（最省事、最加分）
在办结确认卡（ticket.html 的 confirmCard）里，居民点"已解决"后追加 1–5 星评分 + 可选一句话（可复用语音通道）。后端 ResidentTicket 加 rating、rating_comment 两列；街道报表可展示满意度均值。
五、滚动预警条
位置：portal/home.html 顶部（CTA 卡之前）。数据源：给 Notice 加 is_alert 布尔列（比复用 level=预警 更明确，a.txt 建议采纳），查 is_alert=1 且 pinned 且已发布 的最新一条。无预警则整个条隐藏。点击进公告详情；关怀模式下接 speechSynthesis 循环朗读。
六、街道端：不开发，只核对
街道端精力放在演示口径：重点讲"监督者≠执行者"（唯一写权限 task.manage），比加任何功能都值钱。
七、一周执行顺序（按投入产出）
每项落地后统一回归：python -m compileall app 编译检查、scripts/smoke_portal.py 补断言、375×667 手机尺寸截图验证、scripts/audit_all.py 体检。
