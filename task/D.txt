三、使用规则（用户侧）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1) 入口：浏览器打开各自登录页 → 点「注册」→ 填邀请码 / 用户名 / 密码 / 手机号。
2) 居民：注册即激活，登录后按本人手机号只看到自己的诉求，可提交、查询、催办。
3) 内部角色（社区 / 物业 / 街道）：注册后状态为「待审核」，需 admin 在
   「系统管理 → 用户管理」审核通过后才能登录；单位绑定以码为准，无需手填。
4) 一码一人：一张码只能注册一个账号，注册成功后该码即失效，不得转借。
5) 跨区失效：试用版 C 区码只能在 5001 端口用，调整版 B 区码只能在 5002 端口用，
   互相不通用。
6) 管理后台：admin 登录后可为任意角色补发新码（scripts/gen_invites.py）。
7) 手机号必填：居民登录后按手机号关联自己的诉求，漏填可能导致查不到本人的单。

五、管理员如何发放邀请码（部署机命令行操作）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
说明：系统里邀请码的表单校验、绑定单位、一码一人、跨区失效都已就绪，
      但**发码入口是部署机上的脚本**（gen_invites.py），不在网页后台。
      管理员在部署机上按下面步骤操作，把打印出来的码截图发群即可。

【第一步】打开命令行，进入项目目录：
  cd /d E:\program\decrease a\bishe

【第二步】告诉系统往哪个库发码（写进环境变量）：
  给试用版(C区)发码：
    set DATABASE_URL=sqlite:///E:\program\decrease a\bishe\data\trial.db
  给调整版(B区)发码：
    set DATABASE_URL=sqlite:///E:\program\decrease a\bishe\data\dev.db
  注意：上面两行一次只设一个；发完试用版再发调整版时，要先重新 set。

【第三步】生成邀请码（改 --count / --prefix 即可）：
  居民码：   python scripts/gen_invites.py --site C --role resident --org "住武社区居民" --count 10 --prefix C-RES
  社区码：   python scripts/gen_invites.py --site C --role community --org "住武社区" --count 5  --prefix C-COM
  物业码：   python scripts/gen_invites.py --site C --role property  --org "住武物业" --count 5  --prefix C-PRO
  街道码：   python scripts/gen_invites.py --site C --role street    --org "以朵街道" --count 3  --prefix C-STR

  发调整版(B区)时，把 --site 改成 B、--prefix 前缀改成 B-xxx 即可。

【常用参数】
  --site   给哪个区发的码：试用版 C / 调整版 B（只作标记，防止跨区使用）
  --role   角色：resident 居民 / community 社区 / property 物业 / street 街道（不含 admin）
  --org    码绑定的单位全称（注册时自动带出，员工不用手填）
  --prefix 码前缀，建议 C-RES / C-COM / C-PRO / C-STR（最长 8 位）
  --count  生成几张（1~100）
  --list   只列出该库当前未使用的码，不发新码：
           python scripts/gen_invites.py --list

【发放纪律】
  · 一张码只发给一个人，注册成功后该码即作废，不能转给第二个人用。
  · 居民码发给居民；内部角色码谁申报的时候发谁的，别在群里挂一串。
  · 发码脚本不联网，纯本地生成，用完可以把截图发给有需要的人。
